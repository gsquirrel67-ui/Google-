HOME- CLASSROOM — COMMUNITY PUBLISHING SETUP
================================================

This version lets visitors submit HTML games to one shared public list. You need to configure a free Supabase database before the submissions will work.

1. Create a Supabase account at https://supabase.com/ and create a project.
2. In the project, open SQL Editor, create a new query, paste the SQL below, and run it:

create table if not exists public.community_games (
  id bigint generated by default as identity primary key,
  name text not null check (char_length(name) between 1 and 70),
  description text not null default '' check (char_length(description) <= 140),
  html_code text not null check (char_length(html_code) between 1 and 150000),
  created_at timestamptz not null default now()
);

alter table public.community_games enable row level security;

create policy "Anyone can view community games"
on public.community_games for select
to anon, authenticated
using (true);

create policy "Anyone can submit community games"
on public.community_games for insert
to anon, authenticated
with check (
  char_length(name) between 1 and 70
  and char_length(description) <= 140
  and char_length(html_code) between 1 and 150000
);

3. Find your Project URL and anon/public key in Supabase project settings / API keys.
4. Open index.html in a text editor. Near the bottom, replace:
   PASTE_YOUR_SUPABASE_PROJECT_URL_HERE
   PASTE_YOUR_SUPABASE_ANON_PUBLIC_KEY_HERE
   with your own project URL and anon/public key.
   Do NOT use a service_role/secret key in website HTML.
5. Upload index.html to your GitHub home-classroom repository, replacing the old file, then wait for GitHub Pages to redeploy.

IMPORTANT SAFETY / MODERATION NOTES
- Anyone can submit public HTML. This demo allows public submissions and has no account/login, spam protection, or approval queue. Expect spam or abuse if you share it widely.
- You can inspect and delete rows directly in Supabase Table Editor. For a public site, consider adding sign-in, rate limits/CAPTCHA, and an approval queue before allowing broad use.
- The player iframe is sandboxed, but user-submitted code is still untrusted. Don't paste code from strangers into your own browser or add permissions to the iframe casually.
- Keep the anon/public key only with the policies above; never expose a service_role/secret key.
- Follow school rules. This is a community game portal, not a network-filter bypass.


SUBMISSION LOCK BUTTON
----------------------
The website now includes a "Lock submissions" button. By design, that button only locks the submit form in the current browser; visitors can still submit from their own devices. It is useful as a local UI toggle, not a security control.

To lock submissions for EVERYONE:
1. Open Supabase > SQL Editor.
2. Run:
   drop policy if exists "Anyone can submit community games" on public.community_games;
This removes the public insert permission. Visitors can still browse existing games, but no one can submit new games.
3. To re-enable public submissions, run the INSERT policy SQL from the main setup section above again.
Only the Supabase project owner should change database policies.
